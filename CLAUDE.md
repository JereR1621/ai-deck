# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```powershell
npm start          # electron .  -- run from source
.\AI-DECK.cmd      # double-click launcher: runs node_modules\electron\dist\electron.exe on this folder
npm run dist       # electron-builder -> C:\AI-DECK\dist\AI-DECK-Setup-<ver>.exe (NSIS) + AI-DECK-<ver>-portable.exe,
                   # then `postdist` copies the installer to C:\AI-DECK\AI-DECK-Setup.exe. Output lives outside the
                   # repo on purpose: the repo sits under OneDrive and must not sync 100 MB binaries.
npm run pack       # unpacked build only (C:\AI-DECK\dist\win-unpacked\AI DECK.exe), faster for smoke tests
npm run icon       # regenerate build\icon.ico, splash.bmp and logo.png (README) from build\make-icon.ps1
                   # (-Preview <png> for a review sheet on light and dark backgrounds)
```

There is no test suite, lint, bundler, or transpiler. The renderer loads plain `<script>` files and pulls
xterm straight out of `node_modules` via relative paths in `renderer/index.html`, so editing any file
only requires restarting the app (`Ctrl+R` in the Electron window reloads the renderer).

Packaging notes (config in the `build` field of `package.json`):
- `electron` and `electron-builder` must stay in `devDependencies`, or the whole Electron runtime gets
  copied into the asar.
- `asarUnpack` for `@lydell/**` is required: node-pty's `conpty.dll`, `OpenConsole.exe` and `.node`
  files cannot load from inside an asar. Check `dist\win-unpacked\resources\app.asar.unpacked` after
  dependency changes.
- The portable exe re-extracts itself to `%TEMP%` on every launch (~30-40 s on this machine) behind
  `build\splash.bmp`; the installed build starts in ~0.5 s, so the NSIS installer is the normal way to
  ship. Smoke-test with `win-unpacked`, but launch it twice: the first run of a freshly built exe takes
  ~30 s while Defender scans it, which says nothing about the app.
- `electronFuses` hardens the packaged binary (no `NODE_OPTIONS`, no `--inspect`, asar-only loading with
  embedded integrity check). `runAsNode` **must stay `true`**: node-pty's `kill()` calls
  `child_process.fork()` for `conpty_console_list_agent`, which needs `ELECTRON_RUN_AS_NODE`.
  `grantFileProtocolExtraPrivileges` is left at its default because the renderer is served from `file://`.
- `*.pdb` and `*.map` are excluded from the package (node-pty ships ~10 MB of debug symbols).
- `portable.unpackDirName` **must stay `true`**. electron-builder's `NsisTarget.js` turns `false` (and
  the default) into a fixed per-build folder name, and `portable.nsi` runs `RMDir /r` on it before
  extracting — so a second launch wiped the running copy's `conpty.node`/`OpenConsole.exe` and every
  new console died with exit code `-1`. `true` falls through to a unique `$PLUGINSDIR` per launch.
- `main.js` holds `app.requestSingleInstanceLock()`; a second launch only focuses the open window.
- Builds are unsigned; SmartScreen will warn on first run of a downloaded copy. Signing needs a real
  certificate (e.g. Azure Trusted Signing) configured under `win.signtoolOptions` / `win.azureSignOptions`.
- The icon is generated by code, not a hand-drawn asset: edit `build\make-icon.ps1` and rerun
  `npm run icon`. It has three detail levels (>=128, >=48, smaller) so it stays legible at 16 px.
  Watch out for PowerShell's case-insensitive variables there: `$r` and `$R` are the same variable.

Runtime state lives outside the repo, in `%USERPROFILE%\.config\ai-hub\` — the app was renamed from
AI HUB to AI DECK, but this folder deliberately keeps the old name so existing layouts and settings
survive. Do not "fix" it without migrating the folder:
- `config.json` — `lastFolder`, `layout`, `theme`, `palette`, `lang`, and user-defined `agents`
- `ai-hub.log` — appended by `log()` in main and by `window.hub.log()` from the renderer; rotates to
  `.old` past 1 MB. Reading this log is the fastest way to diagnose agent detection and spawn problems.

## What this is

A Windows-only Electron desktop app ("AI DECK", formerly "AI HUB") that opens a real PTY console per AI coding CLI
(Claude Code, Antigravity, DeepSeek-via-OpenCode, OpenCode, plain PowerShell) inside one window, with
a Windows-11-style snapping window manager and a usage/quota panel.

`ai-hub.ps1` is a **separate, earlier implementation** of the same idea (it still says "AI HUB"): a WinForms GUI that launches
the same CLIs as tabs/panes in Windows Terminal (`wt`). It shares only the config dir and log file with
the Electron app — nothing imports it, and it has its own smaller `$Catalog`. Changes to agents in
`main.js` do not propagate there; decide deliberately whether a change belongs in one or both.

## Architecture

Three processes, strict context isolation:

- **`main.js`** — agent catalog, executable detection, PTY lifecycle, usage probes, native dialogs.
- **`preload.js`** — the entire IPC surface, exposed as `window.hub`. Every renderer→main interaction
  goes through this one small file; adding a feature that needs the OS means adding a method here.
  The renderer runs with `sandbox: true`, so the preload may only use `contextBridge`/`ipcRenderer`.

Security boundary in `main.js`: register IPC with the `handle()`/`on()` wrappers, never `ipcMain`
directly — they drop messages whose `senderFrame.url` is not `renderer/index.html`. Navigation,
`window.open`, `<webview>` and permission requests are all denied in `web-contents-created`, which also
forwards renderer warnings/errors (including CSP violations) to the log. `prefs:save` only accepts
`theme`/`palette`/`lang`, because an `agents` key written through it would become a command that
`pty:spawn` runs. `pty:spawn` with `install` requires a matching approval left by
`agent:confirm-install`. `renderer/index.html` carries a CSP allowing only local scripts.
- **`renderer/`** — `app.js` (window manager + UI), `i18n.js` (all UI text), `style.css`, `index.html`.
  No framework, no modules; `app.js` and `i18n.js` share globals (`t`, `LANG`, `I18N`).

### Agents

`BASE_AGENTS` in `main.js` is the catalog. `allAgents()` merges it with `config.json`'s `agents` array
(user entries win on id collision). Each entry: `id`, `title`, `exe` (`null` = bare shell), `tagKey`
(an i18n key), optional `install: { howKey, cmd }`, optional `command`, optional `note`.

`command` wraps the binary instead of running it directly — see `deepseek`, which runs OpenCode with
a `DEEPSEEK_API_KEY` prompt in front of it. Inside `command`, `{exe}` is replaced by the resolved
invocation and any other `{key}` is looked up in `STR[lang]`, so wrapper scripts stay translated.

Everything is launched *inside* `powershell.exe -NoExit`, so the prompt survives the agent exiting.

`resume` (e.g. `--continue`) is appended only when `restoreLayout()` reopens consoles at startup, so
reopening the app picks up each CLI's last conversation in that folder; button clicks start fresh.
For agents without `command`, the invocation falls back to a plain launch if the resume attempt exits
non-zero within 15 s (Claude exits with "No conversation found to continue").

`runShell()` (usage probes) pins `cwd` to `CONFIG_DIR`: otherwise it inherits the portable exe's
per-launch temp folder and `claude -p` registers a new junk project in `~/.claude/projects` each time.

### Executable detection

Deliberately three-layered, because freshly installed CLIs are invisible to an already-running app:
1. `detectWithShell()` re-reads `Path` from the Machine+User registry, caches it in `CURRENT_PATH`,
   and asks that same PowerShell `Get-Command` — so aliases, functions, and shims count as "found".
   Note the comment about PowerShell serializing "not found" as `{}` (truthy in JS) — hence the
   `typeof r.p === 'string'` filter.
2. `whichExe()` as a PATH/PATHEXT fallback, plus a few installer dirs that often miss the PATH.
3. If both fail, `pty:spawn` still invokes by bare name and lets PowerShell's own error show in the
   console. "Not detected" never hard-blocks a launch.

`shellEnv()` deletes every case variant of `PATH` before setting `Path` to `CURRENT_PATH`; Windows env
keys are case-insensitive but a JS object's are not, so skipping that leaves a stale duplicate.

### Usage panel

`USAGE` in `main.js` maps agent id → async probe, each shelling out to that agent's own real source
(`claude -p "/usage"`, `agy -p "/usage"`, DeepSeek's balance REST endpoint, `opencode stats`). Probes
return `{ unit, parts: [{k|raw, v}], detail?, raw? }` or `{ errorKey }` / `{ error }`; the renderer
(`paintUsage`) colours a card by the highest percentage when `unit === 'used'`. `agy` reports quota
*remaining*, so its probe inverts the number to match the others. Agents without a `USAGE` entry simply
do not appear. The DeepSeek key is read inside PowerShell from the user environment and never crosses
into Node or the log.

### Window manager (`renderer/app.js`)

`wins: Map<id, {el, term, fit, agent, zone, alive}>` plus `zones`, an array of `[x, y, w, h]` **desktop
fractions**. A window either has a `zone` index (snapped, positioned by `applyZones()`) or floats.
`autoGrid` re-tiles automatically via `regrid()` and is switched off the moment a window is dragged out
of its zone. `growZones()` splits the largest zone when a new console has nowhere to go, `compactZones()`
closes gaps, `renderDividers()` derives draggable shared borders by matching zone edges within `EPS`.
Layout is persisted debounced (600 ms) through `layout:save` and replayed by `restoreLayout()` at boot.

`fitWin()` is called explicitly after every size change, twice (now and after paint), because
`backgroundThrottling: false` is still not enough to make `ResizeObserver` reliable here; a 1.5 s
interval compares `proposeDimensions()` against the current size as a safety net.

## Conventions

- **Code comments and Spanish UI strings are written without accents** (`instalacion`, `carpeta`,
  `tamano`). Keep that — it is consistent across every file.
- Comments explain *why*, usually documenting a Windows or Chromium quirk that forced the shape of the
  code. Match that density; don't add narration.
- **i18n is mandatory for anything user-visible.** Renderer text goes in both the `es` and `en` blocks
  of `i18n.js` (`t()` falls back to `es`, then to the key itself) and is referenced from HTML via
  `data-i18n` / `data-i18n-title`. Main-process text lives in the parallel `STR` table in `main.js`.
  Errors thrown from main that the user will see are thrown as `new Error('i18n:someKey')` and
  translated by `openAgent()` in the renderer — never throw a raw Spanish or English sentence.
- Themes are five palettes × light/dark, defined twice and kept in sync: CSS custom properties per
  `:root[data-palette=…][data-theme=…]` in `style.css`, and xterm colour objects in `TERM_THEME` in
  `app.js`. Adding a palette means touching `PALETTES`, `PALETTE_LABEL`, `PALETTE_SWATCH`,
  `TERM_THEME`, the `palXxx` i18n keys, and both CSS blocks.
- `readConfig()` strips a UTF-8 BOM before `JSON.parse` — Notepad and PowerShell both write one. Any
  new file this code reads back needs the same treatment.
- Installs are never silent: `agent:confirm-install` shows the exact command in a native dialog, and
  the install itself runs in a visible console window inside the app.
- Logging must never throw; `log()` swallows its own failures by design.
